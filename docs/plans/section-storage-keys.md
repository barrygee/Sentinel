# Browser storage keys by owner

Companion to [section-containers.md §3.7](section-containers.md#37-browser-storage-ownership). It lists every
`localStorage` / `sessionStorage` key the Vue SPA reads or writes, and which part of the app owns it.

When a section becomes its own Module Federation remote (P4), it **keeps these exact key names**. Every remote runs
on the same origin as the shell, so a browser's saved state carries over with no migration.

- **Owner** is the module that writes the key. It uses the ownership map the `sentinel/section-boundaries` lint rule
  enforces (`frontend/vue/eslint-rules/sectionOwnership.ts`).
- **Also read by** lists any other owner that reads the key. Each of these is an implicit contract that must survive
  the split.

Generated by scanning `frontend/vue/src` (non-test files) for storage calls and the `usePersistedObject` /
`usePersistedRef` helpers in `stores/_persist.ts`, as of the P2 finish (#399–#401). Keep it current: a new
persisted key belongs in the table for its owner.

### Per-section keys written by core's shared controls

These are named after a section, but core's generic controls write them on the section's behalf
(`shared/settings/SourceOverrideControl.vue`, `OnlineSourceControl.vue`, `ConnectivityToggle.vue`, `NoUrlOverlay.vue`).
`<ns>` is `air`, `space`, `sea` or `land`.

| Key | Storage | Notes |
|---|---|---|
| `sentinel_<ns>_sourceOverride` | local | `utils/sourceMode.sectionModeStorageKey()` |
| `sentinel_<ns>_<onlineKey>` | local | `utils/domainKeys.onlineKey()`: `onlineDataSourceURL` for air, `onlineUrl` for the rest. **space**'s `SpaceTleOnlineControl.vue` also reads `sentinel_space_onlineUrl` |
| `sentinel_<ns>_<offgridKey>` | local | `utils/domainKeys.offgridKey()`: `offgridDataSourceURL` for air, `offgridSource` for the rest |

## Cross-owner reads (contracts to keep at the split)

1. **`sentinel_sidebar_open`** (core → sdr). The SDR panel, waterfall and decode dock read the sidebar's open state
   from session storage. Same-origin remotes keep this working. A typed shell API (e.g. a `sidebar` capability)
   would make the dependency explicit, and is a candidate for P4.
2. **`overlayStates`** (air → core). The basemap store reads Air's old overlay flags once, to migrate the shared
   roads/names choice. It is harmless if Air is absent: the defaults apply.
3. **`sdrPlaying`** (sdr → shell `index.html`). Required by the early-AudioContext script, and called out in §3.7.
4. **`sentinel_space_onlineUrl`** (core shared control → space). Space's TLE control reads the key core's
   `OnlineSourceControl` writes for the space namespace.

## Findings

- **`userLocation` (resolved 2026-10-05).** `AdsbLiveControl._fetch()` used to read a `userLocation` key that no
  code wrote, so its dead branch was removed. The owner's rule for the ADS-B query centre: **online, the map centre**
  (the browser always sends it); **off grid, the selected receiver's location** — `routers/air.py` swaps in the
  position of the Sentry host behind the Settings › AIR source (`adsb_source.receiver_location()` →
  `hub.sentry.host.location`), falling back to the map centre when none is known.
